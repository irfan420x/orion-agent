## 3. Findings

### F-A13-1 (P2) — `clauseVerbAt` following-word rules read noun phrases as verb phrases (W3)

**Files:** `internal/skills/skills.go` (`clauseVerbAt`, line 1059).

**Reproduction** (probe `internal/skills/w3_audit13_probe_test.go` + `w3_audit13_followup_test.go`, logs `w3-probe-rc17.log` / `w3-probe-rc16.log`, `w3-followup-rc17.log` / `w3-followup-rc16.log`): 33 shapes **LOAD on rc17** but **REJECT on rc16**. Coordinator spot-checked the raw logs: the A-series (28 cases) and followup I/J-series (5 cases) flip exactly as claimed.

| Shape family | Examples (all prefixed "Activate the tool, …") |
|---|---|
| (a) Clause-final plural rule, line 1114 (`if plural && !baseFormNonVerbs[word]`): ANY word at a clause end after a plural/compound subject is a verb | "…the skill and the venv documentation / handbook / manual / library / overview / framework", "…the skills documentation / handbook / summary", "…the skill and the other venv documentation" |
| (b) Preposition/subordinator/adverb-after rules, lines 1130–1145: any non-ambiguous candidate + following word is a verb | "…the skill documentation for beginners / with examples / when ready / quickly"; noun + relative clause: "…the skill documentation that helps", "…the skill handbook which explains" (also compound/plural variants) |
| (c) Bare-plural-object rule, line 1152: checks only the `-s` suffix of the following word, never whether it is a guarded noun in `verbFormNonVerbs` | "…the skill reference/documentation tools", "…the venv documentation tools/settings", "…the skill happy tools", "…the venv reference items" |

**Mechanism:** no following-word rule requires the candidate itself to be verb-shaped first — the rules look only at what follows the candidate. A bare noun at a clause end, a noun followed by a preposition/subordinator/adverb, or a noun followed by a plural word is therefore read as a verb phrase.

**Grading:** P2, not P1 — the shapes are noun-phrase readings, not the clean directive "Activate the tool, the skill" (which still rejects); skills are operator-installed and activation goes through the skill tool, so the validator is a defence-in-depth layer, not the sole control — same grading as F-A12-1.

**Fix direction:** every following-word rule must first require the candidate to be verb-shaped; `that`/`which`/`who` after a noun attaches a relative clause, not a subordinate clause; the bare-plural rule must not fire when `after` is a guarded noun; the clause-final plural rule must not accept a bare word with no verb morphology.

### F-A13-2 (P2) — participle-after rule rejects verb + gerund/participle clauses (W3)

**Files:** `internal/skills/skills.go` (participle-after rule, line 1167).

**Reproduction:** 13 shapes **REJECT on rc17** but **LOAD on rc16**:

| Input | rc17 | rc16 |
|---|---|---|
| Activate the tool, the skill and the venv continue learning / running | REJECT | LOAD |
| Activate the tool, the skills continue learning / working | REJECT | LOAD |
| Activate the tool, the skills stop waiting / learning | REJECT | LOAD |
| Activate the tool, the venv remain waiting / seated | REJECT | LOAD |
| Activate the tool, the skill files running tests | REJECT | LOAD |
| Activate the tool, the venv waiting tests | REJECT | LOAD |

**Mechanism:** the participle-after rule rejects a base-form verb followed by a participle, but `continue`/`stop`/`remain`/`serve` are verbs that legitimately take a gerund/participle complement — rc16 loaded them for the right reason (they are in `baseFormVerbs`). The singular "continues learning" still loads (B13) — only the base-form path loses the clause.

**Grading:** P2, not P1 — fail-closed (safe direction); a validator false-positive on specific prose shapes, not a break of the agent's core function. Same grading as F-A11-1/F-A12-2.

**Fix direction:** exempt listed base-form verbs before a participle; admit participle + bare plural object as verb + object (symmetric with the shipped "running the tests" load case).

### F-A13-3 (P2) — aux-after rule rejects noun-head-subject + copula clauses (W3)

**Files:** `internal/skills/skills.go` (aux-after rule, line 1147).

**Reproduction:** 7 shapes **REJECT on rc17** but **LOAD on rc16**:

| Input | rc17 | rc16 |
|---|---|---|
| Activate the tool, the skill files / notes / guides / reports are ready | REJECT | LOAD |
| Activate the tool, the skill training is ready | REJECT | LOAD |
| Activate the tool, the skill files will help you / have finished | REJECT | LOAD |

**Mechanism:** when the candidate is a noun head ("files", "notes", "training") and the following word is an aux ("are"/"is"/"will"/"have"), the clause exists with the aux as its verb — but the aux-after rule rejects it on the singular/comma path. The compound path still loads ("…the venv files are ready"), so only the singular/comma path loses the clause. The rc17 coordinator documented "the skill files are ready" as an accepted known limitation ("still rejects") — that is inaccurate: it LOADED on rc16, so this is a regression introduced by rc17, not a pre-existing limitation.

**Grading:** P2, not P1 — fail-closed (safe direction); a validator false-positive on specific prose shapes.

**Fix direction:** when the word after the candidate is an aux and the candidate is a noun head, the clause exists with the aux as verb (safe: guarded "tools" still rejects since it returns earlier).
