## 2. P0 — fixed (2, security scope)

- **P0-1 Sandbox chroot escape (confirmed live).** A plain chroot is
  escapable by a uid-0 process in its user namespace; a probe read a
  host canary file from inside the sandbox pre-fix. Fixed by
  replacing chroot with `pivot_root` + lazy `umount2` detach (direct
  syscall via python3 ctypes — `umount(8)` cannot do it because
  `/proc` is deliberately unmounted). Regression tests
  `TestSandboxChrootEscapeBlocked`, `TestSandboxNoDevTTY`.
- **P0-2 Denylist bypasses — 44 probe cases (confirmed, fixed).**
  Wrapper/builtin bypasses (`exec`, `builtin`, `chroot`, `watch`,
  `script`), unblocked namespace/remote wrappers (`nsenter`,
  `unshare`, `systemd-run`, `setpriv`, `capsh`, `ssh`, `scp`,
  `socat`, `expect`), `env -S`/`--split-string`, `$'...'`/`$"..."`,
  variable indirection (`x=rm; $x -rf /`), `find -exec` wrappers,
  file ops on system paths (`cp`/`mv`/`ln`/`chown`/`mkdir`), and
  interpreter payloads (`pypy`, `deno eval`, `bun`,
  `os.chmod`/`os.chown` of system paths). All fixed in
  `internal/security/security.go` with 8 new test functions.

## 3. P1 — fixed (18)

### Core / model / memory / config (5)
- **Deferred tool calls silently lost** — a later multi-call turn
  overwrote the pending list; a single-call turn cleared it. Now
  appends (deduped) and only removes a call when the model executes
  it.
- **Dangling tool-call history poisons later runs** — a run ending
  between the assistant tool-call persist and the tool-result
  persist left history OpenAI/Anthropic reject with 400 on every
  run. New positional `repairHistory` strips/drops dangling calls
  and orphan results before sending.
- **Anthropic consecutive user turns (400)** — the deferred-reminder
  user message after a tool-result user turn was sent as two user
  turns. All consecutive same-role turns now merge.
- **Recall substring matching dropped real facts** — `"write"`
  matched `"writer"`. Now `\b` word-boundary regexp.
- **`Config.Save` non-atomic, lax perms** — plain `WriteFile`
  could tear the config or leave a world-readable `0644` file
  holding API keys/token. Now temp+fsync+rename+dir-fsync, 0600.

### Security / sandbox / tools (8)
- **Audit `Append` head-failure stale state** — a failed head write
  left `lastSeq`/`lastHash` stale, permanently corrupting the chain.
  Now resyncs the tip from disk on head-write failure.
- **Kill / mount / account admin unblocked** — `kill -9 1`,
  `kill -9 -1`, `killall`, `pkill`, `mount`, `umount`, `swapon`,
  `modprobe`, `sysctl`, `passwd`, `useradd`, etc. `kill` now refuses
  PID 1 / negative PIDs; the rest are blocked binaries.
- **`file_read` on a fifo hung forever** — now a bounded,
  context/timeout-aware read (`readFileBounded`, 30s cap).
- **`scrubEnv` leaked credential vars** — added `KEY`,
  `CREDENTIAL`, `AUTH`, `BEARER`.
- **Sandbox hardening** — `/work` remounted `nodev,nosuid`;
  `/dev/tty` removed; root symlink-resolved; `CLONE_NEWIPC` +
  `CLONE_NEWUTS` added.
- **SSRF `isPublicIP` gaps** — 0/8, 100.64/10, 192.0.0/24, 240/4,
  2001:db8::/32, NAT64 added. **Deliberate exception:** 198.18/15
  is NOT blocked — this deployment's egress DNS maps every public
  host into 198.18.245/24, so blocking it broke all web fetches.
- **`process_list` ps fallback leaked full command lines** — now
  `ps -eo pid,comm,stat`.
- **`file_list` read all entries into memory** — now chunked
  `ReadDir(512)`, capped at 10,000 read.

### App / messaging / CLI (3)
- **Telegram `call` embedded up to 10 MiB of raw error body** in
  returned errors. Now a typed `apiError` + 512-rune cap.
- **Poll retried forever on fatal 401/403/409** (revoked token,
  second poller). Now returns an `unrecoverable Bot API error`.
- **`orion telegram test` built the full app** — a corrupt
  `memory.json` made a token check fail with a memory error. Now
  loads config only.

### DeepSeek provider (2)
- **DeepSeek errors labelled "openai:" at 9 sites** — all now use
  the provider name.
- **Config key-required test never covered DeepSeek** — added to
  the loop.

## 5. Seccomp filter — feasible, implemented, wired

- **Verdict:** feasible on this VM with **pure-stdlib Go** — no cgo,
  no libseccomp, no new dependency. Kernel reports filter mode
  (`Seccomp: 2`); a prototype proved `mount`/`unshare`/`keyctl`/`bpf`
  blocked (EPERM) while `/bin/sh`, `python3`, `posix_spawn` work.
  `libseccomp2` is installed but `-dev` headers are absent, so
  `libseccomp-golang` was rejected.
- **Design (flagged): default-ALLOW blocklist, not default-deny
  allowlist.** The sandbox must run arbitrary user tools; enumerating
  every syscall any tool might need is fragile. 46 syscalls EPERM +
  flag-checked `clone`; `clone3` denied with ENOSYS so glibc falls
  back to `clone(2)`. Namespaces + `pivot_root` remain the primary
  containment. A default-deny variant is a follow-up, not a fix.
- **Implementation:** `internal/sandbox/seccomp.go` (classic-BPF,
  label-based assembler, amd64 + arm64 tables),
  `internal/sandbox/cmd/launcher/main.go` (`orion-seccomp` helper,
  installs the filter then `exec`s; exits 126 if install fails),
  wired into `sandbox.Config` (`SeccompLauncher` /
  `DisableSeccomp`, env `ORION_SECCOMP_LAUNCHER`, auto-discovery
  next to the binary / on PATH). On by default when a usable
  launcher is found; graceful fallback + warning otherwise.
- **Tests:** 8 new seccomp tests, all passing — BPF program
  structure, table cross-checks vs Go `syscall` and kernel headers,
  live probe (38 syscalls blocked, legit commands work), negative
  control (same probe unfiltered matches host calibration), clone
  flag probe, fallback/unknown-arch fail-closed. Sandbox package:
  19/19 pass.
- **Wiring (coordinator):** `install.sh` and `Makefile` now build
  and install `orion-seccomp` next to `orion`/`oriond`, so the
  filter engages on a normal install. Verified end-to-end in a
  scratch HOME: `orion`, `oriond`, `orion-seccomp` installed,
  `orion version` reports the build, default config 0600 with the
  DeepSeek entry.
- **Still open:** arm64 table is header-checked but never run on
  arm64 hardware; `python3` is now a sandbox availability
  dependency (the `umount2` detach step) — a static helper would
  remove it; no default-deny variant yet.

## 6. Open P2 items (not fixed)

- **Recall:** single generic token can inject an unrelated fact
  (deliberate threshold); `alreadyVisible` is per-message;
  sentence splitter splits abbreviations; no size cap on tool
  results/history.
- **Providers:** negative `MaxTokens` to OpenAI; Anthropic
  temperature >1 vs config 0–2; empty config file rejected (memory
  treats empty as fresh); 1 MB SSE line cap in all three streamers;
  empty `Chat` final answer returns `""` with nil error; Anthropic
  Stream fallback check inconsistency.
- **Security:** DNS-rebinding TOCTOU (proxy does the dialing —
  decided not to fix); scanner pattern gaps (npm, `xoxo-`, GCP,
  Docker Hub/PyPI tokens); audit-key creation race (fail-closed);
  two `AuditLog` handles interleave (fail-closed); deeper
  variable/interpreter obfuscation; `ip`/`iptables` mutation not
  covered; no PID namespace in the sandbox.
- **Messaging/CLI:** sendMessage has no 429 retry; stranger-chat
  drops are unlogged (no gateway logger); dead `StatusPending`;
  CLI prompt trade-off (accepted); `telegram test` still coupled to
  provider validation in `config.Load`.
- **Timeout design note (DeepSeek):** one stalled attempt can eat
  the whole 120s step budget because the per-attempt client timeout
  (120s) equals the step context (120s). A naive per-attempt cap
  would hurt legitimately slow reasoning models; the fix needs
  design (first-byte/progress deadline distinct from the total
  deadline).
- **60s first DeepSeek attempt stall:** transient server slowness,
  no code defect; production's 120s step context tolerates it.
